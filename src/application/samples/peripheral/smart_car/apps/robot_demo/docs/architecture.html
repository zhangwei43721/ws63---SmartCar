SmartCar · robot_demo 架构图

基于 HiSpark WS63 SDK / Huawei LiteOS · 深入多任务并发、优先级调度与消息环路

Q

核心消息中枢 (motor_q)

深度为 1 的覆盖型队列，汇聚全向指令，避免指令积压造成延迟。

S

400ms 自动防失联安全锁

motor_exec 任务阻塞接收超时将自动下发停车指令，防止小车失控。

M

单轴状态管理机 (robot_mgr)

20ms 高频心跳监测切换。切换模式时，旧模式安全退出、强制执行物理停车。

任务(Task/ISR)一览与调度矩阵

任务名称 源文件 优先级 栈大小 触发与调度机制 核心职责
robot_demo_task robot_main.c 25 (中) 10 KB 系统启动自创建 · 1s 周期 软件看门狗喂狗；调用各服务模块初始化，建立按键中断
robot_mgr core/robot_mgr.c 25 (中) 4 KB 20 ms 周期性唤醒 全局状态机管家：驱动模式切换动作，分发 Tick 事件至对应运行状态
motor_exec core/motor_executor.c 10 (高) 2 KB 阻塞读取 motor_q · 400ms 超时 唯一动力接口：驱动物理电机。超时未收到命令将强制停车安全兜底
sensor_task core/sensor_task.c 23 (中) 2 KB 50 ms 周期性唤醒 读取超声波距离，采用互斥锁 g_state_mutex 安全刷新至全局状态结构体
trace_task core/mode_trace.c 22 (中) 2 KB 20ms 定时或 STOP 事件唤醒 采集 TCRT5000 红外 ADC，运行 PID 算法校正方向并推电机命令，若丢线执行搜索动作
obst_task core/mode_obstacle.c 22 (中) 2 KB 20ms 定时或 STOP 事件唤醒 执行 7 态避障状态机（前进 / 停 / 后退 / 转向等），若有 STOP 信号则自退
udp_task services/udp_service.c 24 (中) 8 KB 网卡接收阻塞 (recv) 开放端口 8888。解析 5 字节 UDP 数据包（包含模式指令、电调及 PID 配置）
ota_tcp_task services/ota_service.c 23 (中) 16 KB UDP 触发后按需建立 创建 8890 端口接收 TCP 固件流，写入Flash升级区，并在屏幕显示升级进度
portal_task services/captive_portal.c 23 (中) 8 KB 初始化建立 · 阻塞等待连接 提供局域网配网服务器（HTTP 80 / DNS 53 劫持），统一处理模式切换与遥控
wifi_switch services/captive_portal.c 23 (中) 4 KB 一次性执行任务 异步切换 AP 模式至 STA 模式，持久化存储 Wi-Fi 凭证
voice_wd services/voice_service.c 29 (极高) 2 KB 事件响应 + 定时器 对 UART 接收的语音进行看门狗延时看护，无新指令则执行自动超时保护停车
ui_task services/ui_service.c 28 (极高) 2 KB 阻塞读取 ui_msgq 统一 OLED 屏物理 I2C 操作出口，解决多任务并发访问造成的数据混叠和花屏
SLE 回调 services/sle_service.c — — 星闪协议栈线程回调 星闪连接建立后，接收与 UDP 对齐的 5 字节包并注入驱动链
按键 ISR robot_main.c 中断 — GPIO3 外部下降沿边沿触发 中断防抖（200ms 限制），无缝闭环轮询当前状态：STOP → TRACE → OBSTACLE → REMOTE → STOP

消息流：以 motor_q 队列为核心

所有物理运动来源（远程 UDP / 星闪 / Web Portal）、本地传感器处理（红外循迹 / 超声避障）及系统主控器（robot_mgr 异常干预）产生电机指令时，均通过统一包装函数 motor_executor_push_cmd() 强行塞入深度为 1 的 motor_q。高频控制覆盖陈旧指令，motor_exec 任务以其阻塞特性实现指令的有序消费。

核心数据通道定义

物理通道/原语 实现类型 数据流生产者 数据流接收者 系统级交互语义
motor_q LiteOS 消息队列 (Depth=1) 控制源: UDP / SLE / Web / 语音 / 循迹 / 避障 / 状态机切换 motor_exec 动力引擎 高频覆盖：只执行最新一条动力指令。400ms 未取到指令则强制物理刹车。
ui_msgq LiteOS 消息队列 (Depth=4) robot_mgr 切换 / OTA 服务 / UDP 心跳 ui_task 界面任务 保障 I2C 驱动接口串行调用，规避图形混叠与多任务锁冲突问题。
g_voice_event LiteOS 共享事件集 (osal_event) UART 串口接收中断 voice_wd 软件狗 通知任务线程有新语音触发，重刷新看门狗倒计时。
g_trace_event / g_obst_event LiteOS 共享事件集 (osal_event) 状态机注销流程 exit() trace_task / obst_task 异步无损唤醒：当外部退出该模式时，通知任务以极快响应度释放资源、退出业务环路。
g_state_mutex LiteOS 互斥锁 (Mutex) sensor_task 距离 / 循迹红外 / 按键中断切换 udp_task / portal_task HTTP 查询 保护共享物理状态，防止在局域网轮询读取与本地硬件高频刷新时发生踩内存。

物理运行模式状态机

robot_mgr 任务以 20 ms 为周期检测变量 g_status。当其发生漂移时，自动执行闭环重构动作： 1) 推送物理零动力安全刹车 (0,0) → 2) 优雅调用注销函数 exit() 并自销毁业务任务 → 3) 执行新状态挂载函数 enter() 启动业务流 → 4) 每 20 ms 周期轮训执行对应模式的 tick()。

0 CAR_STOP_STATUS · 待机模式

Enter: 调用物理阻尼刹车，电机零输出。

  • Tick: 500ms 高阶渲染待机屏（显示AP配网状态、IP地址）
  • Exit: 无释放需求

1 CAR_TRACE_STATUS · PID循迹

Enter: 从物理闪存NV读 PID 配置 → 挂载 event 信号 → 动态建立 trace_task

  • Tick: 挂空（由 trace 任务高频自处理）
  • Exit: 发送全局 STOP 事件并等待任务销毁 → 推送物理停车指令保护

2 CAR_OBSTACLE_AVOIDANCE · 避障

Enter: 重置避障子状态机至 FORWARD (前进) → 动态建立独立 obst_task

  • Tick: 挂空（由避障状态机线程循环执行）
  • Exit: 注入退出事件信号 → 回收运行空间并强制关闭输出

3 CAR_WIFI_CONTROL · 移动遥控

Enter: 初始化系统并设置物理待命停车状态。

  • Tick: 无操作（控制流转为异步：直接由外部网络接口或星闪回调输入）
  • Exit: 强制阻断物理动力链，进入物理断电防护
按键 (GPIO3 中断) 物理环路轮转流程：停止 (0) ➔ 循迹 (1) ➔ 避障 (2) ➔ 遥控 (3) ➔ 停止 (0)

开机引导启动序列 (Power-on Sequence)

  1. 内核入口 app_run(robot_demo_entry) 被 LiteOS 唤醒，创建看守任务 robot_demo_task (Prio 25, 10KB 存储空间)。
  2. 初始化 robot_mgr_init()： 加载系统 NV 分区参数 ➔ 初始化 H桥电机/超声测距/红外ADC驱动 ➔ 依次激活 OLED/UDP/OTA/SLE/Captive Portal ➔ 创建高频 50ms 测距 sensor_task ➔ 设立状态互斥锁 ➔ 绑定消息队列 motor_q 与其主导任务 motor_exec ➔ 最终跑通 robot_mgr 状态机心跳。
  3. 初始化语音服务 voice_service_init()：建立通信消息环路，初始化串口 UART 中断回调，挂载 voice_wd 看护看门狗。
  4. 初始化物理交互 robot_key_init()：将 GPIO3 脚配制成高优先级硬件中断，建立外部下降沿信号防抖，挂载 mode_switch_isr。
  5. 主循环退出初始化流程，陷入对系统硬件看门狗的周期性周期喂狗 (uapi_watchdog_kick) 和 1s 周期休眠阻塞。
