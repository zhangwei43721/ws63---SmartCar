任务(Task/ISR)一览与调度矩阵

任务名称 源文件 优先级 栈大小 触发与调度机制 核心职责
car_main_task car_main.c 25 (中低) 4 KB 自启动创建 · 事件驱动 初始化各服务模块；检测模式切换；按键中断绑定
trace_task core/mode_trace.c 22 (高) 2 KB 模式激活创建 · 20ms 周期 采集 TCRT5000 红外 ADC + 超声波，运行 PID 算法校正并下推电机命令
obst_task core/mode_obstacle.c 22 (高) 2 KB 模式激活创建 · 20ms 周期 执行 7 态避障状态机（前进/停/后退/转向等），内嵌超声波测距
udp_task services/udp_service.c 24 (中) 8 KB 网卡接收阻塞 (recv) 端口 8888 监听。解析 5 字节 UDP 包（控制/模式/PID/OTA），WiFi 配置命令
wifi_mgr services/wifi_mgr_service.c 20 (高) 2 KB 消息队列驱动 WiFi 状态管理：STA/AP 切换、连接失败恢复、事件分发（GOT_IP/FAIL/STOPPED）
ota_tcp_task services/ota_service.c 23 (中高) 16 KB UDP 触发后按需建立 端口 8890 接收 TCP 固件流，写入 UPG 暂存区，校验后请求升级重启
portal_task services/captive_portal_service.c 23 (中高) 8 KB AP 模式下启动 HTTP 80 / DNS 53 劫持配网，Web 页面配置 WiFi，遥控指令转发
voice_task services/voice_service.c 29 (低) 2 KB 阻塞读取 voice_rx 队列 消费 UART 接收字节，解析运动/模式命令，超时自动停车
ui_task services/ui_service.c 28 (低) 4 KB 阻塞读取 ui_msgq 统一 OLED I2C 操作出口，解决多任务并发访问导致的花屏
SLE 回调 services/sle_service.c — — 星闪协议栈回调 接收 5 字节数据包，通过 car_proto_handle_packet 注入控制链
按键 ISR car_main.c 中断 — GPIO3 下降沿 · 200ms 消抖 物理轮询切换模式：STOP → TRACE → OBSTACLE → REMOTE → STOP

消息流总览

系统有两条核心数据通路：电机控制（各模式直接调用 bsp_motor_push_cmd()，无中间队列，见 bsp_motor.c:L78）与 模式切换（通过 mode_q 队列投递 ModeCmdMsg，由状态机消费并执行切换，见 car_main.c:L210）。

核心数据通路定义

物理通道/原语 实现类型 数据流生产者 数据流接收者 系统级交互语义
bsp_motor_push_cmd() 直接函数调用 控制源: UDP / SLE / Portal / 语音 / 自动业务线程 L9110S 电机物理驱动 各执行模式独占式直接操控。切换时由 car_main_task 强行清空输出防暴冲。
mode_q LiteOS 消息队列 (Depth=4) GPIO 按键 ISR / UDP 遥控 / SLE / Web Portal car_main_task 主循环 模式指令的防抖与串行化入口。主任务依据事件周期分发切换流程。
ui_msgq LiteOS 消息队列 (Depth=4) 网络状态机 / 模式转换器 / OTA 进程 ui_task 显示线程 将并发的屏幕刷新请求串行化，规避 I2C 总线多线程竞争导致的硬件花屏问题。
voice_rx LiteOS 消息队列 (Depth=32) UART 串口接收中断 (ISR) voice_task 命令处理器 保障字符级串口接收的吞吐率，有效解耦外部离线语音包解析耗时。
wifi_mgr 队列 LiteOS 消息队列 (Depth=8) 系统初始化 / 断线事件回调 / UDP 配网命令 wifi_mgr 守护服务 执行 STA 连接重试、热点状态退出的核心管理模块。

物理运行模式状态机 (Finite State Machine)

car_mgr 阻塞监听模式切换队列 mode_q，收到指令后执行退出/进入切换，保障平滑控制。

0 CAR_STOP_STATUS · 待机模式

Enter: 调用物理阻尼刹车，电机零输出。

  • Tick: 500ms 高阶渲染待机屏（显示AP配网状态、IP地址）
  • Exit: 无释放需求

1 CAR_TRACE_STATUS · PID循迹

Enter: 从物理闪存NV读 PID 配置 → 挂载 event 信号 → 动态建立 trace_task

  • Tick: 挂空（由 trace 任务高频自处理）
  • Exit: 发送全局 STOP 事件并等待任务销毁 → 推送物理停车指令保护

2 CAR_OBSTACLE_AVOIDANCE_STATUS · 避障

Enter: 重置避障子状态机至 FORWARD (前进) → 动态建立独立 obst_task

  • Tick: 挂空（由避障状态机线程循环执行）
  • Exit: 注入退出事件信号 → 回收运行空间并强制关闭输出

3 CAR_WIFI_CONTROL_STATUS · 移动遥控

Enter: 初始化系统并设置物理待命停车状态。

  • Tick: 无操作（控制流转为异步：直接由外部网络接口或星闪回调输入）
  • Exit: 强制阻断物理动力链，进入物理断电防护
按键循环：待机 (0) ➔ 循迹 (1) ➔ 避障 (2) ➔ 遥控 (3) ➔ 待机 (0)

循迹模式流程 (mode_trace · trace_tick_once)

trace_task 每 20ms 唤醒执行 trace_tick_once()：采集三路红外 → 拼装 3-bit 状态 → 查表得误差 → PID 差速转向。

传感器状态编码表

枚举 L M R 含义 PID 误差 速度缩放
000 0 0 0 全白 — 丢线 进入丢线恢复
001 0 0 1 仅右 → 严重偏左 +2.0 0.6
010 0 1 0 仅中 → 居中 0.0 1.0
011 0 1 1 中+右 → 轻微偏左 +1.0 0.9
100 1 0 0 仅左 → 严重偏右 -2.0 0.6
101 1 0 1 左+右 → 异常/十字 0.0 1.0
110 1 1 0 左+中 → 轻微偏右 -1.0 0.9
111 1 1 1 全黑 — 十字路口 0.0 1.0

避障模式状态机 (mode_obstacle · 7 态循环)

obst_task 每 20ms 唤醒，通过定时器事件推进状态机。遇到障碍物时执行"刹→退→刹→转→稳→测"循环，直到找到出口。

WiFi 网络连接流程

系统上电后根据持久化 NV 配置自动选择连接路由器（STA）或开启配网热点（AP）。

Captive Portal 配网流程

零配置设备自建 AP，利用 DNS 劫持强制拉起配网网页，实现轻量化交互。

OTA 固件升级流程

本系统采用双分区升级（A/B 双备份机制）。运行时在 A 区处理固件下载并写入暂存区，重启后由 Bootloader 进行差分还原与分区切换。

OLED 刷新同步机制

OLED 基于 I2C 总线传输（标准 400KHz 高速模式），该总线无原生硬件互斥。系统采用“消息队列队列化”将所有总线写操作收纳在单一任务中执行，规避多并发冲突。

开机引导启动序列 (Power-on Sequence)

  1. 内核系统入口 app_run(car_demo_entry) 注册调用，分配核心栈空间并建立 car_main_task 守护线程。
  2. 底层外设 BSP 链初始化： 配置信息闪存入库 ➔ 物理 H 桥 PWM 定时器挂载 ➔ HC-SR04 定时器捕获开启 ➔ 循迹 ADC 多通道映射 ➔ OLED 物理驱动挂载。
  3. 上游网络与数据业务服务唤醒： 创建事件队列 mode_q ➔ 绑定 GPIO3 硬件消抖中断 ➔ 开启配网服务 ➔ 载入星闪(SLE)回调 ➔ 唤醒 wifi_mgr 根据 NV 选择自启动机制。
  4. 系统进入 20ms 主物理大循环：喂狗重置、周期轮询执行当前活跃模式的 tick() 控制业务。
